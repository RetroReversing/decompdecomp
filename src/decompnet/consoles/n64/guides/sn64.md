# SN Systems N64 GCC

SN64 GCC 2.8.1 and 2.7.2 build 0001 are distinct compiler/assembler profiles.
They are alternatives to KMC, not interchangeable GCC version labels.

The app preprocesses with that release's cppn64, runs its original cc1n64 and
asn64 through wibo, then converts the PsyQ object to big-endian ELF using a
pinned PCSX-Redux converter. The ordinary linker and byte comparison decide
the match. A familiar-looking disassembly or a low score is not proof.

Use try_compiler on existing C before proposing a compiler range. Try several
nontrivial functions in that part of the game, including calls, data accesses
and floating point. Library code may use a different compiler from game code.
Do not replace a whole game's compiler because one small function matches.

SN64 2.8.1 defaults to -O2 -G0 -mips3 -mgas -meb -mcpu=VR4300 -mhard-float -mfp64.
Build 0001 does not accept -mcpu=VR4300; its default profile omits that option
and -mfp64. search_flags can test optimisation and small-data settings.

SN64 2.8.1 needs ASN64 2.78: an older assembler rejects its %hi/%lo operands.
If an older installation contains only cc1n64.exe, reinstall it in Compilers
& tools to obtain its pinned preprocessor and assembler too. Installation
still requires explicit acceptance of proprietary tools.

The converter needs a C++20 host compiler and zlib headers at first install
(Xcode Command Line Tools on macOS; g++ and zlib1g-dev on Linux/WSL). It is
built once; matching does not rebuild it for every function.
